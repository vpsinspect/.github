# Security Policy

VpsInspect tools are designed to inspect and audit live servers—often with elevated (`sudo`/`root`) privileges. Because of that, we treat security vulnerabilities, command injection, privilege escalation, and supply-chain risks with the highest priority.

## Supported Versions

Security fixes are applied to the latest release on the default (`main`) branch.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, please report them privately using **GitHub Private Vulnerability Reporting**:

1. Go to the affected repository's **Security** tab.
2. Select **Advisories** → **Report a vulnerability**.
3. Include as much detail as possible:
   - Affected repository, version/commit, and operating system
   - Steps to reproduce or proof-of-concept
   - Impact assessment and any suggested remediation

## What to Expect

- **Acknowledgement:** Within 48 hours of submission.
- **Triage & Status Update:** Within 5 business days.
- **Coordinated Disclosure:** We work with reporters to verify fixes and publish a GitHub Security Advisory before public disclosure.

## Safe Harbor

Good-faith security research conducted on your own systems or test environments—without accessing third-party data or disrupting services—is welcome and appreciated.
